# A7 Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Admin Overview board health, Invites revoked/used-by/copy, Firmware tags/boards/GitHub/paging/Promote, and a
Demozoo line on Scan.

**Architecture:** Cross-tenant reads in `src/lib/admin-queries.ts`; pure rules in a new `src/lib/admin-board-health.ts`
and `src/lib/admin-firmware.ts`; one migration (0049, `invites.revoked_at`); one new route
(`POST /api/admin/firmware/[id]/promote`). Server pages stay server components; buttons are small client components.

**Tech Stack:** Next.js App Router (read `node_modules/next/dist/docs/` before route/page code), drizzle-orm/Postgres,
zod, vitest (unit + `vitest.db.config.mts`), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-admin-a7-design.md`

## Global Constraints

- Texts and test ids exactly as the spec writes them.
- "Current release" = highest `sequence` whose notes do not start "TEST build" and whose version is not an e2e version
  (`TEST_RELEASE_PATTERNS`, `TEST_BUILD_NOTES_PATTERN` in `src/lib/firmware-releases.ts`).
- Online = `last_seen_at` within `STALE_AFTER_MS` (`src/lib/device-state.ts`); use the constant, never a literal.
- Only `(admin)` pages and `api/admin` routes import `admin-queries.ts`; every admin route calls `requireSuperAdmin()`.
- Migration 0049 is generated with `pnpm db:generate` (schema TS edit first); implementers never run `db:migrate`
  against production — the controller does.
- Self-host parity: no our-deployment-only dependency (the copy link uses the browser origin; the GitHub repo comes
  from `WEBADF_FIRMWARE_REPO` with the importer's default).
- House rules file binds (no `git add -A`, no stash, own PIDs only, e2e on PORT=3100 one at a time < 9 min, no commit
  after red, commit trailer lines).

## Review Focus

1. A revoked code must never sign up — including a code revoked while a sign-up is in flight (claim's WHERE carries it).
2. Promote must refuse a bench-marker image even if the operator removes "TEST build" from the notes.
3. A device with a NULL `firmware_version` or `last_seen_at` must not crash the distribution or attention lists.
4. e2e runs share the live DB: overview/firmware counts must be asserted relative to seeded rows (data-version rows,
   seeded device names), never as absolute totals.
5. Paging with `?page=` garbage (0, -1, "abc", 9999) clamps, never 500s.

### Task 1: Invites — revoked state and Used by (server)

**Files:** Modify `src/db/schema/devices.ts` (invites: `revokedAt: timestamp('revoked_at', { withTimezone: true })`),
generate `drizzle/0049_*.sql` + meta; modify `src/lib/invites.ts` (`claimInvite` WHERE `revoked_at is null`; new
`revokeInvite(code)` → `'revoked' | 'consumed' | 'missing'`, idempotent for an already revoked code; new
`recordInviteConsumer(rawCode, userId)` best effort); `src/app/api/admin/invites/[code]/route.ts` uses `revokeInvite`
(204 revoked, 409 consumed, 404 missing); `src/lib/auth.ts` `user.create.after` calls `recordInviteConsumer(
readInviteCode(context?.body), user.id)` in its own try/catch (log, never throw), before or after the bootstrap but
independent of it; `src/lib/admin-queries.ts` `InviteState` adds `'revoked'` (first in the CASE), rows add
`usedByEmail: string | null` (left join `auth."user"` on `consumed_by_user_id`) and `consumedAt`; `adminCounts`
`liveInvites` excludes revoked.
**Tests (DB, new `src/lib/invites.db.test.ts` or extend the existing one):** revoke keeps the row with state revoked;
revoke twice → 'revoked' both times; revoke consumed → 'consumed'; claim of a revoked code fails; recordInviteConsumer
sets the id once and never overwrites; adminListInvites returns usedByEmail; liveInvites excludes revoked.
Also update `e2e/admin-invites.spec.ts` "A revoked code disappears" → shows state Revoked and no Revoke button, and
add: a revoked code is refused at /sign-up (see `e2e/invite.spec.ts` for the sign-up helper).
Run: unit + DB tests, `npx tsc --noEmit`, e2e admin-invites + invite (desktop).

### Task 3: Overview — board tiles, firmware distribution, Needs attention

**Files:** new `src/lib/admin-board-health.ts` (pure): `attentionReasons(row, current, now)` →
`{ kind: 'error'|'behind'|'offline', text }[]` with the spec's texts (use `relative()` from device-state.ts for
"<relative time>"), `sortAttention(rows)`, `orderDistribution(rows, releasesBySeq)`; `src/lib/admin-queries.ts`:
`adminBoardCounts()` `{paired, online, seen7d}`, `adminFirmwareDistribution()` (devices seen in 7 d grouped by
firmware_version, joined to `firmware_releases` for sequence), `adminAttentionCandidates()` (devices with error in
24 h OR seen in 7 d; joined to the org owner's email — check `src/db/schema` for how an org's owner/member is stored
and use the earliest member if there is no owner role), `currentReleaseSql()` helper shared with Task 4;
`src/app/(admin)/admin/page.tsx` renders the spec's sections and test ids.
**Tests:** unit for admin-board-health (each reason, thresholds at the boundaries, unrecognised version = behind,
null firmware_version, null last_seen_at, order); DB for the three queries across two orgs; e2e admin-guard: seed two
devices (`e2e/device-helpers.ts` `seedDevices`) with a unique e2e firmware version string and recent last_seen_at,
assert the `fw-dist-row[data-version=<that>]` count is 2, and a seeded device with a fresh `last_error_at` shows in
`attention-row[data-device-id=<id>]`; update the existing overview-count test only if its selectors changed.
Run: unit, DB, tsc, e2e admin-guard (desktop).

### Task 4: Firmware — tags, boards, GitHub link, paging, Promote

**Files:** new `src/lib/admin-firmware.ts` (pure): `stripTestPrefix(notes)` (removes leading `TEST build` then any of
` -–—:·,.` and spaces), `githubReleaseUrl(semver, notes, repo)` (null for TEST or non `x.y.z`), `clampPage(raw,
pages)`, `FIRMWARE_PAGE_SIZE = 25`; share the repo default as an exported constant used by `src/lib/firmware-import.ts`
too; `src/lib/firmware-releases.ts` `listReleasesFull` gains paging (`limit`, `offset`) and a total count, plus
`boards` per version (count of devices with that firmware_version) and `isCurrent`; new
`src/app/api/admin/firmware/[id]/promote/route.ts` per spec §3 (zod body; read bytes with
`firmwareStore.readStream(blobPath)` into a Buffer, ≤ `FIRMWARE_MAX_BYTES`; `refuseImageMarkers(bytes, notes)`; update
notes only where id matches AND notes still like 'TEST build%' — the WHERE makes a double promote a 409);
`src/app/(admin)/admin/firmware/page.tsx` (tags, boards, GitHub link, paging, Promote button) and new
`src/components/admin/promote-release-button.tsx` (client modal; router.refresh() after success; shows the done text).
**Tests:** unit for admin-firmware; DB/route test for promote (404, 409 release, 400 notes, 409 marker image, success
leaves sha/signature/sequence unchanged) — store the test image through `firmwareStore` the way
`e2e/device-helpers.ts publishTestRelease` or existing firmware DB tests do; e2e admin-firmware: publish an e2e TEST
release (`publishTestRelease` with notes "TEST build e2e …"), Promote it, see `fw-tag-release` on its row; paging
links exist when there are > 25 rows (or assert "Page 1 of" text and absence of Newer on page 1).
Run: unit, DB, tsc, e2e admin-firmware (desktop).
