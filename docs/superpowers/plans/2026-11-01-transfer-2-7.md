# Transfer 2.7: writing off stops a file, one Web App row, a commodity with an icon -- Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transfer 2.7 (1) aborts an absolute-path FILE being received the moment writing goes off, (2) shows the
two consent switches as one row `Web App: [x] Read [x] Write` in a tidied window, (3) runs as a commodity (Exchange
Show/Hide/Enable/Disable/Kill, a pop-up hotkey, the close gadget hides, a second start pops up the first) and (4)
ships a Workbench tool icon of its own, generated from a source in the repo, with the commodity tooltypes.

**Architecture:** (1) lives in the portable core (`core/rx_proto.c`), host-tested with `test/fakefs.h`: a new
`rx_switch_changed()` the window calls when a switch flips, and the same check at the top of every data chunk in
`rx_feed`. The aborted file's remaining bytes are drained and discarded; the `ERR <id> readonly …` goes out after the
last byte, because the board ignores `ERR` while it is in `AS_DATA` (firmware `amiga_send.c` run(): only
`AS_FILE_SENT` and `AS_AWAIT_OK` take `ERR`). (2)-(3) are the Amiga front end only (`amiga/gui.c`, a new `amiga/cx.c`
for the broker and the Workbench tooltypes, `amiga/net.c` for Disable). (4) is a host script
`tools/receive/icon/make_transfer_icon.py` that writes a DiskObject from `tools/receive/icon/transfer-icon.txt`
(ASCII art, two images) plus a committed `tools/receive/dist/Transfer.info`; the driver disk build uses it.

**Tech Stack:** C99 core (host `cc -Wall -Wextra -Werror`); amiga-gcc 6.5 pinned image `-m68000 -Os` (gadtools,
asl, workbench, commodities, icon libraries, all V37); Python 3 (icon); FS-UAE on Kickstart 2.04/3.1/3.2, xdftool;
macOS `osascript` (System Events key codes) to type into FS-UAE for the interactive checks.

**Spec:** `docs/superpowers/specs/2026-10-31-net-volumes-writes-design.md` §2 (§2.4 the switches) and §9; the
operator's requests of 2026-11-01 (items 1-4 as relayed by the coordinator) are the spec for everything new here.
Templates: `docs/superpowers/plans/2026-10-31-transfer-2-5-writes.md`, `2026-11-01-transfer-2-6.md` (their rulings

## Review Focus

1. **Writing off in the middle of a `replace`**: the old file must survive byte for byte and no `.webadf-rx` stay.
   Task 1 `writing_off_mid_replace_keeps_the_old_file`.
2. **The board after the abort**: no protocol error, the next FILE (relative, or absolute once writing is on again)
   works on the same connection, and the hello goes stale only after the ERR. Task 1
   `the_connection_is_usable_after_the_abort`.
3. **Off then on again before the next byte** must not resume a file whose temp is gone (it would write into a closed
   handle). Task 1 `back_on_during_the_drain_still_fails`.
4. **A lost connection during the drain**: one FAILED event, nothing written, no crash on the closed handle. Task 1
   `a_lost_connection_during_the_drain`.
5. **The window hidden and shown again** keeps the folder text, both switches, the Trust button state and the list;
   no gadget call on a closed window. Task 3, FS-UAE hide/show check with screenshots.

## Plan rulings

- **R1 (drain, then ERR):** the board ignores `ERR <id>` in `AS_DATA` (`amiga_send.c` switch has no `AS_DATA` case for
  lines), so an early ERR would be lost and the board would wait in `AS_AWAIT_OK` until "no OK" (60 s + size/4 ms),
  then drop. Transfer therefore reads and discards the rest and answers after the last byte, exactly when an `OK`
  would have gone. Cost if wrong: none on the wire (the board already handles ERR in `AS_AWAIT_OK`, as for a CRC
  mismatch).
- **R2 (delete now):** the temp file is closed and deleted when the switch flips (the window calls
  `rx_switch_changed`), not at the end of the drain; `rx_feed` checks too, so the core is safe without the call.
- **R3 (no resume):** switching back on during the drain does not resume; the file still ends `readonly`. Cost if
  wrong: the web app's user copies once more.
- **R4:** the abort text is today's `writing is off in Transfer`; the window's row says `failed: writing is off in
  Transfer`; no new status line (the switch's own "Writing off" status stays).
- **R5 (FS-UAE flip):** decided in Task 2 by measurement: if keys typed into FS-UAE with `osascript` can move the
  Amiga pointer (Left-Amiga + cursor keys) and click (Left-Amiga + Left-Alt), an FS-UAE scenario unticks Write while
  a fake board sends a slow 400 KB `replace`; otherwise host tests alone, said in the report.
- **R6 (one row):** `Web App:` is a borderless TEXT_KIND gadget's left label, so it right-aligns with `Save files to:`
  exactly as GadTools places that label; `Read` and `Write` are checkbox right labels. Both checkboxes sit in the
  column of the folder string gadget.
- **R7 (tidy):** every row ends 6 px from the right border, as it starts 6 px from the left (2.6's right column touched
  the border); the list is sized in whole lines so the bottom margin equals the others (2.6 had one empty line).
- **R8 (commodity only for the window):** `shell_main` gets no broker (no window to show; chip RAM on 512 KB). A Shell
  `Transfer GUI` is a window start: it gets the broker with the defaults (no tooltypes from a Shell).
- **R9 (missing commodities.library):** the window runs as 2.6 (close gadget quits) and the status line says once
  `No commodities.library: running without Exchange`.
- **R10 (second start):** a second window start finds the broker (`CBERR_DUP`); the first gets `CXCMD_UNIQUE` and
  shows its window; the second exits at once (RETURN_OK). Files it was given (shift-clicked icons, `GUI SEND`) are
  not queued (2.6 queued them in a window that could not listen either); a Shell `Transfer GUI` prints
  `Transfer is already running: its window is shown`. `Transfer SEND` from a Shell hands off as before.
- **R11 (Disable):** Exchange Disable closes the board's connection (a file mid-way fails "connection lost" as any
  drop) and the listener; status `Disabled in Exchange`; Enable listens again (`Listening on port 6800`, or `Could not
  listen on port 6800` and a retry each second). Disabled also deactivates the hotkey (commodities does that).
- **R12 (Quit route):** a GadTools menu `Project`: `Hide` (Amiga-H, disabled without a broker) and `Quit` (Amiga-Q);
  Exchange Kill quits; Ctrl-C to the process still quits.
- **R13 (hotkey):** `ctrl alt w`, checked against every `CX_POPKEY`/hotkey tooltype on the 2.04, 3.1 and 3.2
  Workbench disks (Task 4 step 1); a clash picks `ctrl alt t`.
- **R14 (icon):** `tools/receive/icon/transfer-icon.txt` is the source (two 4-colour images, palette indices
  0 grey, 1 black, 2 white, 3 blue); `make_transfer_icon.py` writes a classic OS 2 DiskObject (WBTOOL, no position,
  `do_StackSize` 32768, tooltypes) deterministically; `tools/receive/dist/Transfer.info` is committed and pinned by
  sha256 in `tools/receive/receive-info.sha256`; the driver disk build copies it instead of deriving Transfer.info
  from Rob's PaulaNET Config icon.

static void writing_off_mid_replace_keeps_the_old_file(void) {
    static char data[40000]; char l[400]; int i;
    for (i = 0; i < 40000; i++) data[i] = (char)('a' + i % 26);
    setup(1, 1); ff_put(&F, "Work:Keep.txt", "old", 3, 0, ""); hello4();
    file4(l, "r", data, 40000, "Work:Keep.txt", "replace"); feed(l); drain();

    CHECK(!has("Work:" RX_TMP_NAME), "the temporary file goes at once");
    { int w = F.writes; feedn(data + 20000, 19999); drain(); CHECK(ob_n == 0, "nothing answered before the last byte");

static void the_connection_is_usable_after_the_abort(void) {
    char l[400];
    setup(1, 1); hello4();

    CHECK(!rx_hello_stale(&S), "not while the rest is drained");
    CHECK(feed("def") == 0, "no protocol error"); drain();

and after `rx_write_on`:

```c
/* Transfer 2.7: the owner's switches changed. An absolute FILE being received stops now when writing is off: its
   temporary file is deleted, the rest of its bytes are read and dropped, and ERR <id> readonly follows the last one. */
void rx_switch_changed(rx_session *s);
```

`rx_proto.c`, after `rx_ferr`/`fail_file` helpers (before `finish_file`):

```c
void rx_switch_changed(rx_session *s) {
    if (!s->in_data || !s->cur_mode || s->cur_off || rx_write_on(s)) return;
    if (s->cur_open) { s->fs->close_w(s->fs->ctx); s->cur_open = 0; }
    s->fs->remove(s->fs->ctx, s->cur_tmp);
    s->cur_off = 1;
}
```

`finish_file`, first lines:

```c
    if (s->cur_off) {   /* plan ruling R1: answered after the last byte, when the board listens for it */
        s->cur_off = 0; s->in_data = 0;
        reply_err(s, s->cur_id, "readonly", "writing is off in Transfer");
        emit(s, RX_EV_FAILED, s->cur_id, s->cur_path, s->cur_size, 0, "writing is off in Transfer");
        return;
    }
```

`rx_feed`'s data branch: call `rx_switch_changed(s);` first, and write only while not off:

```c
            rx_switch_changed(s);
            if (!s->cur_off && !s->cur_write_failed && s->fs->write(...) != 0) { ... }
```

`on_file`: set `s->cur_off = 0;` with the other `cur_*` resets. `rx_disconnected`: remove the temp only when
`!s->cur_off`, and clear `cur_off`.
