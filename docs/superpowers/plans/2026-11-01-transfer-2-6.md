# Transfer 2.6: deletes take only what they mean (protocol 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transfer 2.6 speaks protocol 5: `READY 5 <b> <w>`, `DELETE <rid> <len>:<path> one` (exactly one object; a
non-empty drawer is `notempty`), and a drawer DELETE that first renames the drawer to a hidden name in its parent so
nothing saved by its old path meanwhile is deleted with it.

**Architecture:** Everything lives in the portable core (`tools/receive/core/rx_proto.c`), host-tested with
`test/fakefs.h`; the Amiga and POSIX glue already have every hook needed (`w_rename`, `w_delete`), so the Amiga side
changes only its version string. The rename-first delete reuses 2.5's walk unchanged (the path is the stack, plan
2.5 W5): `req_path` holds the hidden path the walk descends, `req_arg` (unused by DELETE in 2.5) keeps the original
path for the owner's words and the rename back.

**Tech Stack:** C99 core (host `cc -Wall -Wextra -Werror`; Amiga amiga-gcc 6.5 pinned image, `-m68000 -Os`), TypeScript
fake board and scenarios (vitest, tsx), FS-UAE on Kickstart 2.04/3.1/3.2, xdftool.

**Spec:** `docs/superpowers/specs/2026-10-31-net-volumes-writes-design.md` §9 (with §1-§2). Template:
`docs/superpowers/plans/2026-10-31-transfer-2-5-writes.md` (its rulings W1-W16 stand).

## Global Constraints

- Kickstart 2.04 floor, any 68000; `build.sh` compiles with no warning.
- Shell stack 8 KB (2.4 measured deepest 3,012 B): no recursion, no new stack buffer over 64 B in the delete path; the
  walk keeps the one 256-byte path in the session.
- The core stays portable (no stdio, no Amiga headers in `core/`).
- **Wire contract (verbatim):**
  - hello `WEBADF 5 <key>` -> `READY 5 <b> <w>`; protocol 1-4 hellos answered exactly as 2.5 does; a hello of 6 or
    newer is answered as 5.
  - `DELETE <rid> <len>:<path> one` (protocol 5 only; on protocol 4 the trailing token is `ERR <rid> bad …`): delete
    exactly that object -- a file, or a drawer only when it is empty; a non-empty drawer -> `ERR <rid> notempty
    <len>:<text>`; nothing inside anything touched; `DONE <rid> 1`. Same refusal codes otherwise; a link is deleted as
    a link.
  - Drawer DELETE without `one` on protocol 5: Rename the drawer within its parent to `.webadf-del-XXXXXXXX` (8 hex
    digits derived from the rid; another suffix if taken), then empty and delete it exactly as 2.5 (DEL every 50, same
    codes, ERR text relative to the ORIGINAL drawer, `DONE <rid> <n>` as 2.5). On a stop, Rename it back; if that name
    was taken meanwhile, leave it and say in the ERR text where the rest is. If the first Rename fails, delete in place
    as 2.5. A file DELETE is unchanged. Protocol 4: exactly as 2.5.
  - `$VER: Transfer 2.6`; FS-UAE send-scenarios `ver` checks 2.6.
- Git: never `git add -A`, never `git stash`; stage by name; no trailers. Never touch `src/` or `wifi-floppy/`. No
  merge, push, driver-disk build, or production.
- FS-UAE: one run at a time; stop only the PID `uae-test.sh` started; GUI mode ends by touching `<work>/stop`; each
  Bash call foreground and under 9 minutes.

## Review Focus

1. **A file saved into the drawer by its old path while the delete runs** survives (the point of §9). Task 2
   `a_file_saved_by_the_old_path_survives`.
2. **A delete that stops leaves the drawer where the owner had it** (refusal, writing switched off, connection lost):
   renamed back; if the old name was taken, the ERR text names the hidden drawer. Task 2
   `a_stop_renames_it_back`, `writing_off_mid_delete_renames_it_back`, `a_lost_connection_renames_it_back`,
   `the_old_name_taken_says_where_the_rest_is`.
3. **`one` never touches anything inside**: a non-empty drawer keeps every entry, a link's target is untouched. Task 1
   `delete_one_*`.
4. **Protocol 4 unchanged byte for byte**: `one` is `bad`, a drawer delete is in place (no rename call). Task 1
   `one_on_protocol_4_is_bad`, Task 2 `protocol_4_deletes_in_place`.
5. **A hidden name that does not fit or cannot be made** (path over 255 bytes, every suffix taken, the rename refused
   with another error): delete in place, never fail for it. Task 2 `the_first_rename_failing_deletes_in_place`.

## Plan rulings (decisions §9 left open)

- **X1 — The hidden name is `.webadf-del-` + `%08lx` of CRC-32(rid) + i**, i = 0..7 for successive suffixes (20
  characters). Cost if wrong: none on the wire; the server never needs the name.
- **X2 — "Taken" is DOS error 203 (object exists) from Rename**: try the next suffix; any other error, eight 203s, or a
  hidden path over 255 bytes -> delete in place as 2.5. Cost if wrong: a delete in place keeps 2.5's (known) risk.
- **X3 — `one` asks AmigaDOS, not a listing:** `DeleteFile` refuses a non-empty drawer (216) atomically; 216 -> 
  `notempty` with Fault's text. No pre-check (a pre-check races). 216 stays `io` everywhere else (protocol 4 identical).
- **X4 — Every stop renames back**: a refusal, writing switched off mid-walk (the rename back is the undo of
  Transfer's own rename, so it runs although writing is off), and a lost connection (best effort, unreported).
- **X5 — The name-taken text** is `the rest is in <hidden name>: <2.5's text>`, cut to 79 bytes; the hidden drawer is
  in the original's parent, so its name suffices. If the rename back fails for any reason, the same text.
- **X6 — The owner's words and every event name the original path**, never the hidden one.
- **X7 — `one` on a protocol 5 DELETE with any other trailing token** is `bad`, as 2.5.
