# Firmware 1.23.1 (protocol 5: `DELETE ... one`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The board speaks protocol 5 to Transfer 2.6: hello `WEBADF 5`, `READY 5 <b> <w>`, the poll's `rxv=5`, and the
request `DELETE <rid> <len>:<path> one` relayed only at protocol 5 -- while Transfer 2.5 (`READY 4`) and 2.4 (`READY 3`)
are served exactly as by 1.23.0.

**Architecture:** `amiga_req.c` learns one more request kind, `AR_DELETE_ONE` (the DELETE line with a literal trailing
` one`; pure, host-tested). `amiga_send.c` says `WEBADF 5`, parses `READY 5 <b> <w>`, treats protocol 4 and 5 alike for
writes, and answers a `DELETE ... one` itself `old` below protocol 5. `device_client.c` accepts protocol 5 for the poll's
`&rxv=`. No new state, no buffer growth.

**Tech Stack:** C11 on RP2350 (pico-sdk, lwIP raw TCP); host tests `wifi-floppy/firmware/test/run.sh` (harness.h
`CHECK`, `CHECK_EQ_INT`, `RUN`, `REPORT`).

**Spec:** `docs/superpowers/specs/2026-10-31-net-volumes-writes-design.md` §9 (protocol 5), §3 with its amendments
(N1-N6); template plan `docs/superpowers/plans/2026-10-31-firmware-1-23-net-writes.md`.

## Global Constraints

- Hello `WEBADF 5 <key>` when requests are on; else as 1.23.0 (`WEBADF 2 <key>` / `WEBADF 1`).
- `READY 5 <b> <w>` counts only as the answer to a protocol 5 hello. `READY 4 <b> <w>` counts as the answer to a protocol
  4 or 5 hello (Transfer 2.5 answers a protocol 5 hello so: protocol 4). `READY 3 <b>` to 3-5, `READY 2` to 2-5, anything
  else 1 (as 1.23.0).
- Writing (`as_write`, dest rows) at protocol 4 and 5 alike.
- Poll: `&rxv=<2|3|4|5>&browse=<0|1>&write=<0|1>` (write `0` below 4).
- Request line `DELETE <rid> <len>:<path> one`: the path a valid write field (1-255 bytes, no control byte), then exactly
  ` one` to the end of the line. Any other tail after the path is malformed (skipped, counted).
- `DELETE ... one` goes to Transfer only at protocol 5. At protocol 3 or 4 the board answers
  `ERR <rid> old 31:Transfer 2.6 or newer is needed`; below 3 `old` as 1.23.0; not connected `norx` as 1.23.0.
- Transfer's answer codes (`notempty` included) pass through as the other ERR lines do: the board does not read them.
- `FIRMWARE_SEMVER` 1.23.1.
- SRAM: no `.data`/`.bss` growth expected (one enum value, one string literal in flash).
- `test/test_amiga_send.c` is Latin-1: ASCII only in new text.
- Repo rules: stage named files only (never `git add -A`), no `git stash`, no commit trailers, never pattern-kill, no
  publish/install, never touch `src/` (web) or `tools/receive/`.

## Review Focus

1. **Transfer 2.5 behind a 1.23.1 board:** it answers `WEBADF 5` with `READY 4 1 1` (confirmed in
   `tools/receive/core/rx_proto.c` on_hello: `peer_v = v >= 4 ? 4 : ...`); protocol 4, writes on, `DELETE ... one`
   answered `old` by the board and never sent. Task 2 `transfer_2_5_answers_ready_4_to_a_protocol_5_hello`.
2. **A path that itself ends in ` one`:** `DELETE d 10:Work:a one` is a plain drawer DELETE of `Work:a one` (the length
   decides), relayed at protocol 4. Task 1 `a_path_ending_in_one_is_a_plain_delete`.
3. **Near-miss tails:** ` ONE`, ` one ` , ` onex`, ` one one`, `  one`, ` on` are malformed and skipped. Task 1.
4. **A READY 5 to an older hello** (protocol 2 hello) counts as 1; a malformed `READY 5 1` counts as 1. Task 2.
5. **Protocol 3 and `DELETE ... one`:** answered `old` (not `readonly`): Transfer 2.4 knows no writes at all, but the
   server only sends it at rxv=5, so the board's word is that Transfer is too old. Task 2.

## Rulings made while planning (relay to the operator)

- **P1 (cost if wrong: the web app shows the board's text, not its own):** a `DELETE ... one` below protocol 5 is
  answered `ERR <rid> old 31:Transfer 2.6 or newer is needed` -- at protocol 3 and 4 alike (`old` before `readonly`).
- **P2:** `AR_DELETE_ONE` is its own kind (a write), relayed byte for byte; `ar_take` copies the rid with `DELETE `'s
  length.
- **P3:** `READY <n>` with n above the hello's protocol, or n > 5, counts as 1, as 1.23.0 treats an unknown READY.
- **P4:** the poll path does not grow (`rxv=5` is one digit); `dc_set_req` accepts 2-5.

static void delete_one_is_its_own_kind(void) {
    load("DELETE d 8:Work:old one\nDELETE e 8:Work:old\n");

    CHECK(strcmp(R.rid, "d") == 0, R.rid);

static void a_path_ending_in_one_is_a_plain_delete(void) {
    load("DELETE d 10:Work:a one\n");
    CHECK(ar_take(&R, NULL) && R.kind == AR_DELETE, "the length decides");
}
static void malformed_delete_tails_are_skipped(void) {
    load("DELETE a 6:Work:a ONE\nDELETE b 6:Work:a one \nDELETE c 6:Work:a onex\nDELETE d 6:Work:a one one\n"
         "DELETE e 6:Work:a  one\nDELETE f 6:Work:a on\nDELETE g 6:Work:a \nMKDIR h 6:Work:a one\nDELETE ok 6:Work:a one\n");
    int bad = 0;
    CHECK(ar_take(&R, &bad) && strcmp(R.rid, "ok") == 0, R.rid);
    CHECK_EQ_INT(bad, 8);
}
