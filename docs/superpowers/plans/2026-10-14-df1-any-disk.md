# DF1: any disk, not only the next disk of a set -- Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the board's DF1 setting **On**, every Mount offers **DF0 or DF1**; a disk mounted into DF1 (a
"pick") lives in DF1's own PSRAM slot (`SLOT_NET`), read-only, whatever DF0 holds or does; **Eject DF1** on the card
drops it and DF1 follows the set again. Ships as firmware release **1.12.0**.

**Architecture:**
- **Server.** `devices` gains `df1_disk_id` (the pick) and `df1_version` (its cursor). `mountToDf1` / `ejectDf1`
  are single conditional UPDATEs (the `saveSecondDrive` pattern) with the §3.1 rules in the WHERE. A DF0 mount of
  the picked disk, a setting change away from On, and a disk delete all clear the pick and move the cursor in the
  same write. The poll gains `?df1Ack=` (inequality wake, the `displayAck` rule) and a `df1` body key
  `{"v":N,"sha256":"<hex>"|null}` on every body to a board that sends `df1Ack`. `/api/device/image/net/<sha>`
  also serves a standard DD ADF of the board's own organization, as a DD WFAD.
- **Firmware.** A pick record `dc_df1_pick_t` beside the preload record. `dc_take_df1` lifts and blanks `df1`
  from every 200 body and acks it at once. `dc_df1_pick_step` fetches the pick into `SLOT_NET` from the `net`
  route (ejecting DF1 first), with the driver disk's block on failure. `dc_df1_want`: On with a pick ->
  `SLOT_NET` once verified (empty until then), On without one -> today's rule, Network unchanged, Off -> none.
  Leaving On drops the pick.
- **Web.** One pure module, `src/lib/df1-pick.ts`, holds §3.1's rules, their words and the card's DF1 line, so
  the buttons, the card, the drive menu and the server never disagree. Mount buttons (disk rows, disk sets, the
  disk's files page, library cards) gain a DF1 choice when the board's DF1 setting is On.

**Tech Stack:** C11, pico-sdk 2.3.0 (RP2350); host tests via `wifi-floppy/firmware/test/run.sh`. Next.js 16.3.2
(App Router route handlers), drizzle-orm 0.45 + hand-trimmed SQL migrations applied with `psql`, zod 4, vitest 4,
Playwright 1.62.

**Spec (binding):** `docs/superpowers/specs/2026-10-14-df1-any-disk-design.md`. Also binding: HANDOFF.md §3bk
(fw 1.11.1: DF1's ID answer, `_df1_hd_ok`, DF1 HD cannot work behind CN11) and §3bj (Network, `SLOT_NET`, the
`net` route, the driver disk's own block). The Phase 3 plan
`docs/superpowers/plans/2026-10-12-paulanet-phase3-network-setting.md` is the code this plan extends (its rulings
6, 12 and 24 describe `SLOT_NET` and the DD WFAD).

## Rulings (made while planning; each open to revision by the operator)

1. **`df1_disk_id` is `text`, not `uuid`.** The spec says `uuid`; `disks.id` is `text` (`src/db/schema/catalog.ts:135`)
   and a foreign key must match the referenced column's type.
2. **`ON DELETE SET NULL` is only the backstop.** It clears the column without moving `df1_version`, so the board
   would never be told (a cursor, not a flag). `deleteDisk` / `deleteGame` already eject DF0 holders first
   (`ejectHolders`, `src/lib/disk-delete.ts:43`); they now also clear DF1 picks through `ejectDf1Holders`, which
   moves the cursor. The FK covers paths that do not go through them (an org deleted by the admin plane, whose
   devices go in the same batch).
3. **The board acks `df1Ack` when it TAKES the record, not after the load.** The spec (§5) says "ack once handled
   (applied, or refused and reported)". But the server sends `df1` on every body, so the record is never lost, and
   the load is reported through `df1Sha256` already. Acking only after a multi-second fetch -- or while the preload
   gate refuses (unsent saves, a firmware download) -- would make the hold answer every poll at once for that whole
   time: a poll storm. So: ack = the `v` of the latest body; the load is the pick step's business.
4. **A pick that is not (yet) verified leaves DF1 empty.** Spec §5 names only "verified pick -> SLOT_NET" and "no
   pick -> today's rule". While a pick loads, or after its fetch failed, DF1 never shows the set's next disk for a
   moment: the Amiga sees one disk change, empty -> the pick.
5. **`DC_POLL_BODY_BYTES` 1536 -> 1664.** The worst-case poll body with `df1` (a 64-hex pick) is 1,557 B by
   `device-limits.test.ts`'s own model (1,458 + 99), over the 1,536-byte buffer; the firmware refuses a truncated
   body outright. Boards before 1.12.0 send no `df1Ack`, are never sent the key, and keep their 1,458-byte worst
   case inside their own 1,536. Cost: +128 B in each of three static buffers (~384 B `.bss`).
6. **The DF0/DF1 control appears only on a board whose DF1 setting is On.** D1 says Off and Network mount to DF0
   "as today", and §3.1 lists "DF1 is off" as a disabled reason. Both hold: with Off or Network the Mount button is
   unchanged; "DF1 is off" is the server's refusal when the setting changed under an open page. **A fifth reason,
   "Waiting for the board",** covers On chosen but not yet applied (§3.1 rule 1 has no wording for it; it is the
   card's own wording, `secondDriveStatus`).
7. **The drive chip shows DF1 in its menu, not on the chip face.** The chip face has no room at 1280 px
   (`chipSlots`, `src/lib/drive-chips.ts:164`). The menu gets a DF1 line whenever the board runs On, with both
   states in words (the card's line, `df1LineText`).
8. **The pick fetch uses the DF0 preload gate and runs before DF0's preload, one background fetch per pass.** The
   gate (`preload_ok`: no unsent saves, no firmware staging, no held swap) keeps a 900 KB fetch out of a save's way;
   someone asked for the pick, DF0's preload is speculative.
9. **The pick's failures share the `net` route's block (`_net_blocked`, `dc_net_block`).** Spec §5 says "its own
   block (as `dc_net_block`), never DF0's ring". The driver disk and a pick never coexist (Network vs On), the block
   is one digest, retried after `DC_NET_RETRY_MS` (60 s) and cleared by any mode change.
10. **The library card's ring and Eject stay DF0's.** A pick is ejected from the card on /devices (Eject DF1) or from
    the disk's row on the game page. The disk row's holder line says "In <board> (DF1)".
11. **`mountChoice` / `mountChoices` take the disk as an object** (`{ id, sha256, imageFormat, sizeBytes }`), not
    `(diskId, sha256)`, because §3.1 rule 3 needs the format and size. Every caller changes; no default parameter.

## Review Focus

1. **A pick and a DF0 mount in the same poll body, with `df1` ahead of `desired`.**
   - Expected: DF0 fetches desired's disk from the library route into A/B; the pick is recorded and later fetched
     from the `net` route into `SLOT_NET`; neither lands in the other's slot, and DF0's active slot is never evicted.
   - Test: `a_df1_key_never_shadows_desired_and_df0_never_lands_in_slot_net` and
     `df0_mounts_and_next_swaps_never_touch_slot_net` (Task 5).
2. **The same image under two disk rows: DF0 holds row X, the user mounts row Y (same digest) into DF1.**
   - Expected: allowed (rule 4 compares rows); the board loads its own copy into `SLOT_NET`; DF0 untouched.
   - Tests: `df1-pick.test.ts` "compares disk ROWS, not digests" (Task 2);
     `a_pick_with_df0s_digest_loads_its_own_copy` (Task 5).
3. **Switching to Network while a pick is loaded or pending, and a late body that still names it.**
   - Expected: the server clears the pick in the setting's own write; the board drops its pick record on leaving
     On, never fetches a pick in Network, and the driver disk takes `SLOT_NET`.
   - Tests: `second-drive-save.test.ts` "leaving On drops the pick" (Task 2);
     `network_mode_drops_the_pick_and_the_driver_disk_wins` (Task 5).
4. **A board on 1.11.x paired to a server that knows picks.**
   - Expected: it sends no `df1Ack`, so it is never woken for a pick and never sent `df1`; its DF1 choice is
     disabled with "Needs firmware 1.12.0"; the server refuses a direct request with that reason.
   - Tests: poll `route.test.ts` "a MISSING df1Ack ..." (Task 3); `df1-pick.test.ts` firmware refusal (Task 2);
     e2e "the DF1 choice is disabled with its reason" (Task 8).
5. **The picked disk is deleted.**
   - Expected: the pick goes with a cursor bump, so the board ejects DF1 and the card says DF1 follows the set.
   - Tests: `disk-delete-disk.test.ts` "a deleted disk mounted into DF1 leaves it" (Task 2); e2e "deleting the disk
     in DF1 drops the pick and tells the board" (Task 8).

// DF1 any disk (spec docs/superpowers/specs/2026-10-14-df1-any-disk-design.md §3): who may mount what into DF1,
// the words for each refusal, and the card's DF1 line. Pure and client-safe -- no database import -- so the Mount
// buttons, the device card, the drive menu and the server action read ONE set of rules and can never disagree.
import { firmwareAtLeast } from '@/lib/firmware-version';
import { ADF_BYTES } from '@/lib/adfmfm/constants';
import type { NextInfo } from '@/lib/next-disk';

/** The firmware that keeps a disk mounted into DF1 in DF1's own slot (spec §5). */
export const DF1_PICK_FW = '1.12.0';

/** Why a disk cannot go into DF1, first match wins: the setting, the board, then the disk. */
export type Df1Refusal = 'df1_off' | 'waiting' | 'firmware_too_old' | 'not_dd' | 'in_df0';

export const DF1_REFUSAL_TEXT: Record<Df1Refusal, string> = {
  df1_off: 'DF1 is off',
  // Plan ruling 6: On chosen, not yet applied -- the card's own wording (secondDriveStatus).
  waiting: 'Waiting for the board',
  firmware_too_old: `Needs firmware ${DF1_PICK_FW}`,
  not_dd: 'DF1 takes standard DD disks only',
  in_df0: 'Already in DF0',
};

export interface Df1Board {
  secondDrive: string;
  secondDriveReported: string | null;
  secondDriveVersion: number;
  secondDriveAppliedVersion: number | null;
  firmwareVersion: string | null;
  desiredDiskId: string | null;
  mountedDiskId: string | null;
  df1DiskId: string | null;
}

export interface Df1Disk { id: string; imageFormat: string; sizeBytes: number }

/** Spec §3.1 rule 3: an ADF of exactly 901,120 bytes. No HD, HFE, extended or long-track image. */
export function isStandardDd(d: { imageFormat: string; sizeBytes: number }): boolean {
  return d.imageFormat === 'adf' && d.sizeBytes === ADF_BYTES;
}

/**
 * Spec §3.1, all four rules (the org rule is the caller's: the disk passed in is already this org's row).
 * Rule 4 compares disk ROWS: the same image under another row may go to DF1 (spec §8.2).
 */
export function df1Refusal(b: Df1Board, d: Df1Disk): Df1Refusal | null {
  if (b.secondDrive !== 'df1') return 'df1_off';
  if (b.secondDriveReported !== 'df1' || b.secondDriveAppliedVersion !== b.secondDriveVersion) return 'waiting';
  if (!firmwareAtLeast(b.firmwareVersion, DF1_PICK_FW)) return 'firmware_too_old';
  if (!isStandardDd(d)) return 'not_dd';
  if ((b.desiredDiskId ?? b.mountedDiskId) === d.id) return 'in_df0';
  return null;
}

export interface Df1Option {
  enabled: boolean;
  /** The refusal in words while disabled; null while enabled. */
  reason: string | null;
  /** This disk is the one in DF1: the button takes it out. */
  isThisDisk: boolean;
}

/** What a Mount button offers for DF1, or null: the board's setting is not On (D1, plan ruling 6). */
export function df1Option(b: Df1Board, d: Df1Disk): Df1Option | null {
  if (b.secondDrive !== 'df1') return null;
  if (b.df1DiskId === d.id) return { enabled: true, reason: null, isThisDisk: true };
  const r = df1Refusal(b, d);
  return { enabled: r === null, reason: r === null ? null : DF1_REFUSAL_TEXT[r], isThisDisk: false };
}

/** Exactly the fields above, for a client component's props (a DeviceListItem also carries a layout blob). */
export function df1BoardOf(b: Df1Board): Df1Board {
  return {
    secondDrive: b.secondDrive, secondDriveReported: b.secondDriveReported,
    secondDriveVersion: b.secondDriveVersion, secondDriveAppliedVersion: b.secondDriveAppliedVersion,
    firmwareVersion: b.firmwareVersion, desiredDiskId: b.desiredDiskId, mountedDiskId: b.mountedDiskId,
    df1DiskId: b.df1DiskId,
  };
}

export interface Df1Line {
  df1DiskId: string | null;
  df1PickTitle: string | null;
  df1PickDiskNo: number | null;
  df1PickSha256: string | null;
  /** What the board reports DF1 holds. */
  df1Sha256: string | null;
}

/**
 * The DF1 line on the card and in the drive menu (spec §3.3), both states in words. A pick reads "loading" until
 * the board reports holding exactly its digest.
 */
export function df1LineText(d: Df1Line, next: NextInfo | null): string {
  if (d.df1DiskId !== null) {
    const what = `${d.df1PickTitle ?? 'A disk'}${d.df1PickDiskNo !== null ? ` disk ${d.df1PickDiskNo}` : ''}`;
    const held = d.df1PickSha256 !== null && d.df1Sha256 === d.df1PickSha256;
    return `DF1: ${what} — read-only${held ? '' : ', loading'}`;
  }
  if (d.df1Sha256 === null) return 'DF1: next disk of the set — empty';
  return next?.preload === 'ready'
    ? `DF1: next disk of the set — disk ${next.diskNo}`
    : 'DF1: next disk of the set — ready';
}

// DF1 any disk (spec docs/superpowers/specs/2026-10-14-df1-any-disk-design.md §4): the pick's writes and the
// poll's read. Every write is ONE org-scoped UPDATE that moves df1_version with the pick -- the board learns of a
// change only through that cursor (a wake needs a cursor, not a flag).
import { and, eq, inArray, sql } from 'drizzle-orm';
import { getDb } from '@/db';
import { devices } from '@/db/schema/devices';
import { disks } from '@/db/schema/catalog';
import { firmwareAtLeastSql } from '@/lib/display-store';
import { DF1_PICK_FW, df1Refusal, isStandardDd, type Df1Refusal } from '@/lib/df1-pick';

export type MountDf1Outcome = { ok: true; version: number } | { ok: false; reason: 'not_found' | Df1Refusal };

/**
 * Mount a disk into DF1 (spec §4.4). §3.1's board rules live in the UPDATE's WHERE (the saveSecondDrive /
 * saveDisplay pattern): a status report or a DF0 mount landing between a read and this write cannot slip a refused
 * pick through. The disk's own rule (a standard DD ADF of this org) is a property of its row, checked first.
 * not_found covers an unknown disk, another org's disk, and another org's board -- indistinguishable, as for
 * setDesired.
 */
export async function mountToDf1(orgId: string, deviceId: string, diskId: string): Promise<MountDf1Outcome> {
  const db = getDb();
  const [disk] = await db
    .select({ id: disks.id, imageFormat: disks.imageFormat, sizeBytes: disks.sizeBytes })
    .from(disks)
    .where(and(eq(disks.id, diskId), eq(disks.orgId, orgId)))
    .limit(1);
  if (!disk) return { ok: false, reason: 'not_found' };
  const scope = and(eq(devices.id, deviceId), eq(devices.orgId, orgId));
  if (isStandardDd(disk)) {
    const [row] = await db.update(devices)
      .set({ df1DiskId: disk.id, df1Version: sql`${devices.df1Version} + 1` })
      .where(and(
        scope,
        eq(devices.secondDrive, 'df1'),
        eq(devices.secondDriveReported, 'df1'),
        eq(devices.secondDriveAppliedVersion, devices.secondDriveVersion),
        firmwareAtLeastSql(DF1_PICK_FW),
        // Rule 4, by disk ROW (spec §8.2): not the disk DF0 holds or is about to hold.
        sql`coalesce(${devices.desiredDiskId}, ${devices.mountedDiskId}) is distinct from ${disk.id}`,
      ))
      .returning({ version: devices.df1Version });
    if (row) return { ok: true, version: row.version };
  }
  const [b] = await db
    .select({
      secondDrive: devices.secondDrive, secondDriveReported: devices.secondDriveReported,
      secondDriveVersion: devices.secondDriveVersion, secondDriveAppliedVersion: devices.secondDriveAppliedVersion,
      firmwareVersion: devices.firmwareVersion, desiredDiskId: devices.desiredDiskId,
      mountedDiskId: devices.mountedDiskId, df1DiskId: devices.df1DiskId,
    })
    .from(devices)
    .where(scope)
    .limit(1);
  if (!b) return { ok: false, reason: 'not_found' };
  // A refusal that no longer holds when read back (the board caught up between the write and this read) is still
  // a refusal of THIS request: the person presses again.
  return { ok: false, reason: df1Refusal(b, disk) ?? 'waiting' };
}

/** Eject DF1 (spec §3.2): the pick goes and DF1 follows the set again. The new cursor, or null if not this org's. */
export async function ejectDf1(orgId: string, deviceId: string): Promise<number | null> {
  const [row] = await getDb().update(devices)
    .set({ df1DiskId: null, df1Version: sql`${devices.df1Version} + 1` })
    .where(and(eq(devices.id, deviceId), eq(devices.orgId, orgId)))
    .returning({ version: devices.df1Version });
  return row?.version ?? null;
}

/**
 * Every board of the org whose pick is one of `diskIds` lets go of it, with the cursor moved (plan ruling 2): the
 * FK's ON DELETE SET NULL would clear the column and tell no board. Called before the disks are deleted.
 */
export async function ejectDf1Holders(orgId: string, diskIds: string[]): Promise<string[]> {
  if (diskIds.length === 0) return [];
  const rows = await getDb().update(devices)
    .set({ df1DiskId: null, df1Version: sql`${devices.df1Version} + 1` })
    .where(and(eq(devices.orgId, orgId), inArray(devices.df1DiskId, diskIds)))
    .returning({ name: devices.name });
  return rows.map((r) => r.name);
}

/**
 * The poll body's `df1` (spec §4.2): the cursor and the pick's digest, null without one. Not org-scoped by the
 * caller -- the device is authenticated to exactly this row -- but the join is: a pick naming another org's disk
 * row yields null, never that org's digest.
 */
export async function readDf1ForPoll(deviceId: string): Promise<{ v: number; sha256: string | null }> {
  const [r] = await getDb()
    .select({ v: devices.df1Version, sha256: disks.sha256 })
    .from(devices)
    .leftJoin(disks, and(eq(disks.id, devices.df1DiskId), eq(disks.orgId, devices.orgId)))
    .where(eq(devices.id, deviceId))
    .limit(1);
  return { v: r?.v ?? 0, sha256: r?.sha256 ?? null };
}

static bool dc_df1_pick_step_inner(device_client_t *c) {
    dc_df1_pick_t *k = &c->df1_pick;
    k->interrupted = false;           // describes THIS step only
    if (c->state != DC_IDLE_POLL || c->_refetch) return false;
    if (c->_df1_mode != DF1_MODE_NEXT || k->want_sha256[0] == '\0') return false;

        }

    if (dc_net_is_blocked(c, k->want_sha256)) return false;              // the net route's own block (ruling 9)
    if (!c->_preload_ok || !c->_preload_ok(c->_preload_ok_ctx)) return false;   // the preload gate (ruling 8)
    // DF1 may be serving SLOT_NET (the previous pick). Eject it and wait for core0 before a byte is written;
    // false = nothing happened, try on a later pass. The record is kept: it still says what SLOT_NET holds.
    if (!dc_df1_release(c, SLOT_NET)) return false;

    // From here SLOT_NET is being overwritten: no record survives it.
    if (k->sha256[0] != '\0') k->changed = true;
    k->sha256[0] = '\0';
    k->loading = true;
    // A copy: the log below must name what was fetched even if a later body changes want_sha256.
    char sha[65];
    snprintf(sha, sizeof sha, "%s", k->want_sha256);
    wf_logf(WF_INFO, "df1: loading %.12s -> slot %d", sha, SLOT_NET);
    int status = 0;
    dc_fetch_result_t res = dc_fetch_into(c, sha, SLOT_NET, /*observe=*/false, /*interruptible=*/true, &status);
    k->loading = false;

    switch (res) {
    case DC_FETCH_INTERRUPTED:
        // A tap or a write is waiting: nothing failed (no backoff), nothing verified (no record).
        k->interrupted = true;
        c->state = DC_IDLE_POLL;
        return false;
    case DC_FETCH_OK:
        snprintf(k->sha256, sizeof k->sha256, "%s", sha);
        k->changed = true;
        wf_logf(WF_INFO, "df1: %.12s verified in slot %d", sha, SLOT_NET);
        c->state = DC_IDLE_POLL;
        return true;
    case DC_FETCH_INVALID:
        wf_logf(WF_WARN, "df1: %.12s is not a valid DD WFAD -- held off for %lu s", sha,
                (unsigned long)(DC_NET_RETRY_MS / 1000u));
        dc_net_block(c, sha);
        dc_enter_backoff(c);
        return true;
    case DC_FETCH_STATUS:
        if (status == 401) { c->state = DC_HALTED; return true; }      // 401 anywhere halts
        if (status == 400 || status == 404 || status == 422) {
            wf_logf(WF_WARN, "df1: server said %d for %.12s -- held off for %lu s", status, sha,
                    (unsigned long)(DC_NET_RETRY_MS / 1000u));
            dc_net_block(c, sha);
        }
        dc_enter_backoff(c);
        return true;
    case DC_FETCH_NO_REQUEST:
    case DC_FETCH_INCOMPLETE:
    default:
        dc_enter_backoff(c);          // no record; the backoff paces the retry
        return true;
    }
}

const style = { background: 'var(--primary-action)' };

const ejectStyle = { borderColor: 'var(--hairline)', color: 'var(--ink)' };
const ejectCls = 'rounded-lg border px-3 py-1.5 text-[12px] font-semibold disabled:opacity-50';

export function MountAction({ diskId, choices }: { diskId: string; choices: MountChoice[] }) {
  const router = useRouter();
  const [busy, setBusy] = useState(false);
  const [expanded, setExpanded] = useState(false);
  const wrapperRef = useRef<HTMLDivElement>(null);

  // Focus the expanded group itself so a bare Escape (no explicit target)
  // still reaches this wrapper's onKeyDown -- otherwise, with focus left on
  // <body> after the trigger button unmounts, the keydown would never

/**
 * A paired board whose DF1 setting is On and applied (spec 2026-10-14), reporting `firmwareVersion` -- through the
 * real routes: a status report, the setting PATCH, then the report that acks it. Marked seen now, so a request to
 * it reads as pending, not stale.
 */
export async function df1OnBoard(
  page: Page, request: APIRequestContext, firmwareVersion = '1.12.0+gabc1234', name = 'Test Device',
) {
  const { deviceId, token } = await pairDevice(page, request, name);
  const report = (extra: Record<string, unknown>) => request.post('/api/device/status', {
    headers: authHeader(token),
    data: { mountedSha256: null, firmwareVersion, sel1Wired: true, df1Seen: false, ...extra },
  });
  if ((await report({ secondDrive: 'off', driveVersion: 0 })).status() !== 204) throw new Error('status failed');
  const set = await page.request.patch(`/api/devices/${deviceId}/second-drive`, { data: { mode: 'df1' } });
  if (set.status() !== 200) throw new Error(`second-drive failed: ${set.status()}`);
  if ((await report({ secondDrive: 'df1', driveVersion: 1 })).status() !== 204) throw new Error('status failed');
  await getDb().update(devices).set({ lastSeenAt: new Date() }).where(eq(devices.id, deviceId));
  return { deviceId, token };
}
